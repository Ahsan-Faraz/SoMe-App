\section{Summary}
% ===========================================================================
\begin{itemize}
  \item \textbf{Stack:} Supabase (Postgres, Auth, Storage, Realtime) in \code{eu-north-1}, and Next.js 16 on
        Vercel functions in \code{arn1}. There is no other service. No Redis, queue, workers, GraphQL or global
        client store. Nothing measured calls for them.
  \item \textbf{Transport:}
        \begin{itemize}
          \item Server Components read through the DAL (\code{cache()} + \code{getClaims()}).
          \item Hot writes (send, react, mark-read) go from the browser to a Postgres RPC under RLS.
          \item Privileged work (admit, group membership, album password, login by username) runs as Server Actions.
        \end{itemize}
  \item \textbf{Size:} 15 tables and 3 storage buckets. Every table maps to a V1 story. The analysis also dropped
        two tables that looked necessary:
        \begin{itemize}
          \item \textbf{Verification} is a camera photo in the admin DM, so it needs no table of its own.
          \item \textbf{Album unlock} is enforced by short-lived signed URLs issued only after the password check,
                so it needs no table either.
        \end{itemize}
  \item \textbf{Biggest design correction:} the planned per-user Realtime channel for A1 means one Broadcast per
        member per message. That is 460 writes for one post in a 460-member group, the same fan-out the unread
        design avoids. \textbf{Recommendation:} in V1, A1 refetches its single RPC on focus and navigation (\S\ref{sec:rt}).
  \item \textbf{Blocking TBDs for later slices:} account scope, the ads model (AD-001), and direct join.
        Slices 1--10 can proceed on the safe assumptions below. Ads wait for AD-001.
\end{itemize}

\subsection{Frontend contract changes the backend forces}\label{sec:contract}
\begin{enumerate}
  \item \code{getViewer()} returns \code{u-me}. It must return the real \code{auth.uid()} and member state.
        Delete \code{mocks/session.ts} and \code{roleForUsername}.
  \item \code{ChatMessage}:
        \begin{itemize}
          \item \code{reactions} becomes \code{\{emoji, count, mine\}[]}.
          \item \code{comment} becomes \code{replyTo: \{seq, author, snippet\}}.
          \item \code{image}/\code{imageSrc} become \code{thumbUrl} and \code{fullPath} (full URL signed on tap).
          \item \code{timeLabel} is formatted on the server.
          \item Add \code{seq} as the paging cursor.
        \end{itemize}
  \item Group G2 currently offers ``leave and block''. DM-005..007 make delete and block DM-only, so groups show only
        ``Leave''.
  \item \code{ProfileFields} hardcodes demo fields and must render from \code{profile\_field\_defs} (FieldRenderer).
  \item \code{lib/image.ts}:
        \begin{itemize}
          \item It outputs a JPEG data URL. It must output a WebP \code{Blob}, with a JPEG q 0.8 fallback, at
                $\sim$1600 px plus a 256 px thumbnail.
          \item Data URLs in localStorage exceed the quota after a few photos.
        \end{itemize}
  \item Missing UI that V1 stories need (the columns are added now):
        \begin{itemize}
          \item the custom member status editor (GROUP-007)
          \item a ``show sticky posts'' toggle on A10 (STICKY-003)
          \item a forgot-password page (AUTH-006, flow TBD)
        \end{itemize}
\end{enumerate}

\section{Database design}
% ===========================================================================
\subsection{Conventions}
\begin{itemize}
  \item UUID primary keys, except \code{messages}: PK \code{(chat\_id, seq)}.
  \item Every tenant table carries \code{community\_id not null}, including child tables, so RLS filters on an
        indexed local column.
  \item \code{timestamptz} everywhere. Lengths are enforced in \code{check} constraints, so a direct browser call
        cannot bypass them.
  \item Enums use \code{text} + \code{check}, so a new value is a one-line migration.
  \item RLS is on for every table, and policies use \code{(select auth.uid())}.
  \item Two \code{security definer stable} helpers with \code{search\_path = ''} are the only intentional RLS
        crossings: \code{is\_member(community)} and \code{is\_chat\_member(chat)}.
\end{itemize}

\subsection{Transactions (each inside one Postgres function)}
\begin{itemize}
  \item \code{send\_message}:
        \begin{enumerate}
          \item Check membership, block, and state.
          \item \code{update chats set last\_seq = last\_seq + 1, last\_message\_at, preview \ldots\ returning last\_seq}.
                The row lock serializes seq per chat only.
          \item Insert the message.
          \item \code{realtime.send()} to \code{chat:\{id\}}.
        \end{enumerate}
  \item \code{delete\_message}: delete, then recompute the preview from \code{max(seq)} if the deleted message was last.
  \item \code{save\_group}: upsert the chat, upsert 3 info posts, and on create insert the creator as group admin.
  \item \code{set\_group\_member}: insert with \code{visible\_from\_seq = case when history then 0 else last\_seq end},
        or delete.
  \item \code{delete\_dm}: delete the chat row. The cascade removes the other side's access (DM-006).
  \item \code{save\_profile}: update base columns, then replace values per submitted def.
  \item Join trigger on \code{auth.users} insert: creates the pending \code{members} row and the DM with the
        community admin (AUTH-004).
\end{itemize}

\section{API design}\label{sec:api}
% ===========================================================================
``API'' means Postgres RPCs, Server Actions, and one Route Handler. PostgREST is the REST layer, so no extra
REST layer is added.

\subsection{Authentication and authorization}
\begin{itemize}
  \item \textbf{Authentication:} Supabase Auth cookies, refreshed only in \code{proxy.ts}. The server verifies them
        with \code{getClaims()} (local JWT check).
  \item \textbf{Authorization:} always in Postgres (RLS or an in-function check), never only in the UI. Roles:
        \begin{itemize}
          \item \emph{approved member}
          \item \emph{pending member}: own profile, plus the DM with the admin only
          \item \emph{community admin} (\code{members.role})
          \item \emph{group admin} (\code{chat\_members.role}; in V1 only the creator)
          \item \emph{author}: own posts, notes, albums, and ads
        \end{itemize}
\end{itemize}

\section{Performance strategy}
% ===========================================================================
\subsection{Round trips}
\begin{itemize}
  \item One RPC per screen (\S3.1).
  \item \code{getMember()} is shared by layout and page via \code{cache()}.
  \item \code{getClaims()} is local, with no network call.
\end{itemize}

\subsection{Rendering}
\begin{itemize}
  \item \code{cacheComponents} is on: the static shell paints first, and data sits in \code{<Suspense>} with
        \code{RouteSkeleton}.
  \item \code{'use cache'} is used only for the community row, field defs, and group name/headline/info posts
        (invalidated with \code{updateTag}).
  \item It is never used for messages, unread counts, membership, roles, blocks, notes, album access, or verification.
\end{itemize}

\subsection{Hot writes}
\begin{itemize}
  \item Send, react, and mark-read go browser $\rightarrow$ Supabase in the same region.
  \item Send and react are optimistic: send inserts a local row keyed by a client UUID and replaces it with the
        returned seq.
  \item Mark-read runs on open and on leave only.
\end{itemize}

\subsection{Realtime}\label{sec:rt}
\begin{itemize}
  \item One private Broadcast topic \code{chat:\{id\}}, only while a thread is open.
  \item The write RPCs call \code{realtime.send()} in the same transaction.
  \item Topic authorization is an RLS policy on \code{realtime.messages} using \code{is\_chat\_member}, checked at join.
  \item There is no \code{postgres\_changes} subscription.
  \item \textbf{A1 without a per-user channel (recommended change to \code{performance.mdc}):}
        \begin{itemize}
          \item A1 refetches \code{chat\_list} on visibility, focus, and back-navigation.
          \item This costs one query per focus instead of one write per member per message.
          \item If live badges are wanted later, add the per-user channel with a member-count cap, after measurement.
        \end{itemize}
\end{itemize}

\subsection{Database}
\begin{itemize}
  \item The indexes in \S4.2 cover every list. RLS predicates touch only indexed columns.
  \item Targets, checked with \code{EXPLAIN ANALYZE} on seeded data before each slice is done:
        \begin{itemize}
          \item A1 $<$ 20 ms
          \item thread page $<$ 15 ms
          \item search $<$ 50 ms at 5k members
        \end{itemize}
\end{itemize}

\subsection{Payload and bundle}
\begin{itemize}
  \item Lists carry thumbnail URLs. The full image is signed on tap.
  \item A1 refreshes through \code{router.refresh()}, so it ships no Supabase client and stays inside 150 KB gzipped.
\end{itemize}

% ===========================================================================
\section{Scalability}
% ===========================================================================
Follow the \code{scaling.mdc} ladder: measure, then climb one rung.
\begin{enumerate}
  \item \textbf{Now} (up to about 10k members per community):
        \begin{itemize}
          \item one Supabase instance
          \item PostgREST pooling (no direct \code{pg} client, so no Supavisor yet)
          \item stateless functions
        \end{itemize}
  \item \textbf{Messages growth:}
        \begin{itemize}
          \item 1k posts/day for 3 years is about 1M rows.
          \item A keyset read on the PK stays O(log n) at 100M rows.
          \item Hash-partition by \code{chat\_id} only if vacuum or index size is a measured problem.
        \end{itemize}
  \item \textbf{Realtime:} cost scales with viewers of open chats, not members. The plan quota is the ceiling;
        upgrade the plan before adding infrastructure.
  \item \textbf{Search:} bounded by \code{community\_id}. Add \code{pg\_trgm} and partial indexes per hot def before
        any search service.
  \item \textbf{Not needed:}
        \begin{itemize}
          \item Redis: Postgres serves in $<$ 20 ms.
          \item Queues: the only async work is storage cleanup via \code{after()}.
          \item Read replicas and microservices.
        \end{itemize}
\end{enumerate}

\section{Unnecessary or inefficient parts of the current plan}
% ===========================================================================
\begin{itemize}
  \item \textbf{Verification table or workflow:} unnecessary. A camera image in the admin DM plus
        \code{members.state} covers it.
  \item \textbf{Album-unlock table or cookie:} unnecessary. One-hour signed URLs are the session unlock.
  \item \textbf{Per-user A1 Broadcast:} inefficient (\S\ref{sec:rt}).
  \item \textbf{localStorage persistence} for filters, notes, albums, calendar, assignments, and photos:
        \begin{itemize}
          \item per-device, while stories say ``on this account''
          \item exceeds quota with data URLs
          \item exposes ``private'' notes to anyone sharing the device
        \end{itemize}
  \item \textbf{JPEG data URLs from \code{imageDataUrl}:} inefficient. Use WebP Blobs uploaded directly.
  \item \textbf{Redis, queues, a search service, replicas:} unnecessary at V1 scale.
\end{itemize}
